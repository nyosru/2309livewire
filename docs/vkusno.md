# Вкусняжки72

Сайт добавлен в текущий Laravel-проект. Домены: `vkusno.local`, `вкусняжки72.рф` (Punycode: `xn--72-dlcyjau5ar6c5d.xn--p1ai`). Регистрация маршрутов не зависит от домена запроса и работает с кешем маршрутов.

## Запуск

1. Выполнить миграции при развёртывании: `php artisan migrate --force`.
2. Направить DNS глобального домена на существующий сервер Laravel и добавить его в конфигурацию HTTPS веб-сервера. Внешние DNS и сервер в рамках этой задачи не изменялись.
3. Для локального сайта в hosts нужен `127.0.0.1 vkusno.local`, в Caddy — обычная группа приложения `2309livewire`. На текущем компьютере запись hosts уже есть, домен добавлен в `/Users/phpcat/PhpstormProjects/2508caddy_local/caddy/dev.Caddyfile`.
4. Контакты заполнены по карточке 2ГИС: Тюмень, Харьковская улица, 59а, 1 этаж; ежедневно 08:30–21:00; +7 (963) 452-17-13. При необходимости переопределить через `VKUSNO_PHONE`, `VKUSNO_ADDRESS`, `VKUSNO_HOURS` в `.env`. После изменения конфигурации очистить/пересоздать кеш конфигурации Laravel.

Меню и цены хранятся в БД (`vkusno_products`, модель `App\Models\Vkusno\Product`). Миграция `2026_10_22_000002_create_vkusno_products_table` однократно переносит текущие товары из `config/vkusno.php`, сохраняя идентификаторы и порядок. После её применения каталог изменяется через модель товаров; изменения массива `products` в конфигурации на витрину и заказы больше не влияют. Начинки и минимальный срок изготовления торта по-прежнему задаются в `config/vkusno.php`. Это **примерные данные**: заменить перед началом коммерческой работы и установить `VKUSNO_DEMO_MENU=false`. Фотографии иллюстративные, исходники Unsplash перечислены ниже; фото интерьера не является фотографией реального кафе. `VKUSNO_DELIVERY_FEE` — фиксированная стоимость доставки в рублях; пустое/null значение означает индивидуальное согласование, а не бесплатную доставку.

## Заявки

Корзина сохраняется в браузере. Отправка заявки требует согласия на обработку данных, имени и телефона; для доставки обязателен адрес. Для торта требуются начинка, вес и дата минимум за три дня. Сервер сверяет товары с каталогом и рассчитывает цену самостоятельно. Стоимость торта не входит в сумму блюд и согласуется отдельно. Онлайн-оплаты нет. Все заявки ожидают подтверждения кафе.

Заявки хранятся в таблице `vkusno_orders`. `/admin/orders` доступен суперадминистратору кафе и VK-аккаунтам, которым он выдал доступ через панель. Общие email и роли других сайтов проекта доступ не предоставляют. Страница отображает контакты, адрес, состав заказа и пожелания к торту. Автоматические уведомления не подключены: новые заявки нужно проверять на этой странице.

Перед коммерческим запуском дополнить `/privacy` реальными реквизитами оператора и условиями обработки данных. Меню, условия доставки и юридические сведения пока требуют заполнения владельцем. Контакты проверены по карточке 2ГИС 22.10.2026.

## Хранение товаров и заказов

`App\Models\Vkusno\Product` → `vkusno_products`: строковый `id` (сохранены идентификаторы старого каталога), раздел, категория, название, описание, единица продажи (`weight`), цена в целых рублях, изображение, метки и сведения об исходном фото. `inferred_fields` хранится как JSON, `price_is_estimate` отмечает предварительную цену. `is_active=false` скрывает товар и запрещает его заказ; `sort_order` задаёт порядок показа. Витрина, каталог браузера и расчёт заказа используют активные товары из БД.

`App\Models\Vkusno\Order` и миграция `2026_10_22_000001_create_vkusno_orders_table` уже существуют. Контакты клиента, доставка, дата, комментарий, пожелания к торту и статус сохраняются в `vkusno_orders`. Поле `items` содержит снимок идентификатора, названия, цены, количества, единицы продажи и признака предварительной цены на момент заказа. Изменение или удаление товара не меняет полученные заказы.

Применить только миграции этого сайта в контейнере:

```bash
docker exec 2309livewire php artisan migrate --path=database/migrations/2026_10_22_000001_create_vkusno_orders_table.php --path=database/migrations/2026_10_22_000002_create_vkusno_products_table.php --path=database/migrations/2026_10_22_000003_create_vkusno_menu_catalogs.php --path=database/migrations/2026_10_22_000004_create_vkusno_administrators_table.php --force
```


## Панель управления и доступ через ВКонтакте

Вход: `/admin/login`, панель: `/admin`. Ссылка «Управление кафе» находится в подвале сайта.

- `/admin/products`: поиск, фильтр по категориям, создание, редактирование и удаление товаров, загрузка/замена фото, изменение цены, единицы продажи, предварительной цены, видимости и порядка.
- `/admin/categories`: создание, переименование, перенос в другой раздел, порядок и скрытие категорий.
- `/admin/sections`: создание, переименование, описание, порядок и скрытие разделов меню.
- `/admin/orders`: просмотр полученных заявок.
- `/admin/access`: выдача и отзыв доступа по числовому VK ID, только для суперадминистратора.

Настройка суперадминистратора: `VKUSNO_SUPER_ADMIN_VK_ID=5903492` в `.env`. ID взят из уже существующей локальной настройки `VK_ADMIN_ID`. Значение читается через `config('vkusno.super_admin_vk_id')`; если отдельная переменная отсутствует, используется `VK_ADMIN_ID`. На другом сервере необходимо явно настроить ID и обновить кеш конфигурации. Суперадминистратора нельзя удалить через панель. Для остальных VK ID используется таблица `vkusno_administrators`, в которой также записывается ID выдавшего доступ. После отзыва прав следующий запрос к панели отклоняется, включая запросы из уже открытой сессии. Пользователь без доступа не может выдать права себе.

Вход переиспользует `App\Livewire\Auth\Vk::redir()` и `handleVKCallback()` и существующие `services.vk.client_id` / `services.vk.client_secret` (`VK_CLIENT_ID` и `VK_CLIENT_SECRET`). Добавлены проверка одноразового OAuth `state`, обновление идентификатора сессии и возврат в панель. Отдельные клиентские ключи кафе не нужны.

Для приложения VK нужно разрешить callback **на том же домене, с которого начинается вход**: `https://вкусняжки72.рф/admin/auth/vk/callback` (Punycode: `https://xn--72-dlcyjau5ar6c5d.xn--p1ai/admin/auth/vk/callback`). Для локальной разработки — `https://vkusno.local/admin/auth/vk/callback`. Панель задаёт этот адрес на время запроса; глобальный `VK_REDIRECT_URI` других сайтов не изменяется. Разрешённые URI на стороне VK не изменялись автоматически. Реальный вход с согласиями VK необходимо проверить владельцу приложения.

Миграция `000003` переносит существующие разделы и категории из конфигурации и привязывает все уже имеющиеся в БД товары, включая пользовательские категории. `MenuSection` → `vkusno_menu_sections`, `MenuCategory` → `vkusno_menu_categories`, `Product::menuCategory()` → связь по `menu_category_id`. Скрытый раздел или категория исключают свои товары из витрины и оформления заказа. Удалить можно только пустую категорию/раздел; для заполненных есть скрытие. Полученные заказы сохраняют исторические снимки товаров.

Фотографии: JPG, PNG, WebP до 5 МБ и 6000 × 6000 пикселей, диск `vkusno`, папка `public/vkusno/menu/uploads/`. SVG не принимаются. Файлам присваиваются случайные имена, `storage:link` не нужен. Папку загрузок необходимо сохранять при развёртывании и резервном копировании. Старые фото не удаляются автоматически.

Проверки `AdminTest` используют SQLite в памяти, подмену запросов VK и отдельный тестовый диск фотографий. Проверяются изменения каталога, исторические заказы, выдача/отзыв прав, запрет обхода общими разрешениями Spatie и защита OAuth. Реальные запросы к VK и публикация изменений на сервере в тестах не выполняются.


## Вход через MAX без VK

На `/admin/login` добавлен отдельный блок MAX: телефон → одноразовый код → вход. Суперадминистратор разрешает доступ только по телефону в `/admin/access`; VK-аккаунт пользователю не нужен. `VKUSNO_SUPER_ADMIN_PHONE` в `.env` задаёт телефон суперадминистратора, но права активируются только после проверки кода. Перед первым входом пользователь нажимает «Поделиться телефоном» в боте. Подписанный контакт автоматически связывает телефон с MAX ID; вводить ID вручную не нужно.

Общая интеграция с MAX вынесена из кафе в `App\Services\Max`; подробные настройки, команды и примеры для других сайтов/проектов — [docs/max.md](max.md). Используется прямой API MAX, посредников нет. По умолчанию отправка кодов отключена до настройки (`MAX_AUTH_DRIVER=disabled`); для режима собственного бота необходимы токен, проверенные привязки получателей и соответствующие условия MAX для авторизационных сообщений.

Миграция: `docker exec 2309livewire php artisan migrate --path=database/migrations/2026_10_22_000005_create_max_auth_tables.php --force`. Проверки MAX используют отдельную SQLite в памяти и `Http::fake()`. Реальные коды при тестах не отправляются.
